# 模块设计

## 1. 模块划分

### 1.1 common 公共模块

`langchain4j-demo-common`

职责：

- 统一返回结构 `Result`
- 业务异常与错误码
- 公共枚举、常量
- 无业务状态的通用工具类

依赖：无内部模块依赖。

### 1.2 service 服务模块

`langchain4j-demo-service`

职责：

- 对话业务接口与实现
- JPA 实体与 Repository
- 对话消息 DTO
- LangChain4j 消息组装与模型调用编排

依赖：`common`。

### 1.3 biz 接入模块

`langchain4j-demo-biz`

职责：

- 应用启动类
- Web Controller
- 阿里云模型 Bean 配置
- Nacos 配置接入
- 全局异常处理

依赖：`service`、`common`。

## 2. 包结构规范

根包名：`com.ifinance.aicustomer`

```text
com.ifinance.aicustomer
├── common
│   ├── constant
│   ├── enums
│   ├── exception
│   ├── model
│   └── util
├── service
│   ├── dto
│   ├── entity
│   ├── repository
│   └── service
│       └── impl
└── biz
    ├── config
    └── controller
```

## 3. 分层规范

| 层 | 位置 | 规则 |
| --- | --- | --- |
| Controller | biz.controller | 只做参数接收、调用 Service、返回 Result |
| Service | service.service | 业务编排，不出现 HTTP 细节 |
| Repository | service.repository | 数据访问，方法名遵循 Spring Data 规范 |
| Entity | service.entity | JPA 实体，字段与表结构对齐 |
| DTO | service.dto | 接口出入参，使用 Java record |

## 4. 依赖规则

- `service` 不得依赖 `biz`。
- `common` 不得依赖 `service`、`biz`。
- 禁止循环依赖。
- 跨模块调用只使用公开接口与 DTO，不直接暴露 Entity。
