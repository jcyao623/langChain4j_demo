# 数据库设计

## 1. 数据库信息

| 项目 | 值 |
| --- | --- |
| 数据库 | `langchain4j_demo` |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 应用账号 | `chat_app` |
| 地址 | `127.0.0.1:3306`（本机 Docker） |

## 2. 表结构：chat_message

存储用户与 AI 的聊天消息。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| session_id | VARCHAR(64) | NOT NULL | 会话 ID |
| role | VARCHAR(16) | NOT NULL | USER / ASSISTANT / SYSTEM |
| content | TEXT | NOT NULL | 消息内容 |
| model_name | VARCHAR(64) | NULL | 模型名称 |
| prompt_tokens | INT | NULL | 输入 token 数 |
| completion_tokens | INT | NULL | 输出 token 数 |
| total_tokens | INT | NULL | 总 token 数 |
| created_at | DATETIME(6) | NOT NULL | 创建时间 |
| updated_at | DATETIME(6) | NOT NULL | 更新时间 |

索引：

```sql
INDEX idx_session_created (session_id, created_at)
```

## 3. DDL

```sql
CREATE TABLE IF NOT EXISTS chat_message (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id VARCHAR(64) NOT NULL,
  role VARCHAR(16) NOT NULL,
  content TEXT NOT NULL,
  model_name VARCHAR(64) DEFAULT NULL,
  prompt_tokens INT DEFAULT NULL,
  completion_tokens INT DEFAULT NULL,
  total_tokens INT DEFAULT NULL,
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  INDEX idx_session_created (session_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='AI 客服聊天消息表';
```

完整初始化脚本见 [sql/init.sql](../sql/init.sql)。

## 4. 设计说明

- `role` 使用枚举字符串，避免依赖序数，便于阅读与扩展。
- `content` 使用 TEXT，满足长文本回复。
- `token` 字段预留，用于后续成本统计与模型调优。
- 会话维度查询走 `session_id, created_at` 联合索引。
- 演示环境使用 JPA `ddl-auto: update` 自动建表；生产环境建议改为 `validate` 并使用 Flyway 管理迁移。
